# 三档推荐与 AKShare 接入（2.6）

目标同时覆盖命中质量、扣费收益和回撤，但没有足够样本外数据时不能宣称“更准”。本次完成的是可核验的风险过滤、时间归档和三档条件观察；没有重训或替换既有冠军模型。

## 与 daily_stock_analysis 的取舍

参考上游截至 `f9e7b778c48c914af4e0c69dd301e6907d7ea5f9` 的实现：

| 可借鉴点 | Stock King 的实现与补足 |
| --- | --- |
| 趋势、均线乖离、量能和买点纪律 | 保留 MA5/10/20 趋势，按三档加入 MA5 乖离、ATR 延伸和压力/支撑距离比的真实否决条件；空间不够不只写风险提示。 |
| 结构风险和资金守卫 | 与分钟结构、20/20 日同刻成交额基线、同行业同刻广度及资金方向共同检查；数据缺失不补齐推荐名额。 |
| 多源行情和可读理由 | 腾讯/新浪互备，末尾重新核验每一档的行情时间；保存指标、来源、判断原因、未通过项。 |
| AI 综合新闻和技术信息 | 保留手动 AI 复审；AI 文案不能覆盖缺数据、陈旧报价或未通过本地检查的结论。未接到原始新闻证据时，催化和预期差仍列未知。 |
| 复盘与策略评估 | 保存三档及被拒绝样本，保留旧规则基线；收益检验必须包含未交易日、交易限制、成本和时间外样本，不用仅推荐股票的涨跌比例证明有效。 |

参考源码：[趋势分析](https://github.com/ZhuLinsen/daily_stock_analysis/blob/f9e7b778c48c914af4e0c69dd301e6907d7ea5f9/src/stock_analyzer.py)、[上游仓库](https://github.com/ZhuLinsen/daily_stock_analysis)。技术分、AI 综合分和实测胜率是不同口径，不互相转换。

## 三档入场检查

| 条件 | 稳健 | 均衡 | 激进 |
| --- | --- | --- | --- |
| MA5 最大正乖离 | 3% | 5% | 7.5% |
| 相对 MA5 最大 ATR 距离 | 1.5 | 2 | 2.5 |
| 最小结构空间/风险比 | 2 | 1.5 | 1.2（无历史压力时可保留突破条件观察） |
| 日线多头排列 | 必须 | 必须 | 必须通过分钟突破/延续检查 |
| 财报利润、每股收益、经营现金流 | 全部为正且已披露 | 展示已知值与缺口 | 展示已知值与缺口 |
| 14 日解禁比例合计上限 | 3% | 5% | 8% |

解禁比例相对各批次解禁前的流通盘，合计是保守风险筛查量，不是精确摊薄率。已披露净利润预告为首亏、续亏、增亏、预减时三档均暂避。未知事件风险进入观察。上述阈值是明确可审查的初始纪律，尚未由收益数据拟合，输出 `validationStatus=rules_unvalidated`，不输出胜率。

三档在“当日机会”内切换。旧“策略分组”里的 SafeBound 20/60 日、BalancedRank 5/20 日、LimitPulse 1–3 日仍走原有模型训练及发布门槛，和本次 T 至 T+5 入场过滤分开。

## 接入的数据与时间边界

一次全市场批量读取最近两个已结束报告期财报、当前及上一报告期业绩预告、未来 14 日解禁，共五个请求，成功结果缓存六小时；单请求隔离进程超时，最多三路并发。免费接口并不保证 SLA。

| AKShare 接口 | 使用字段 | 防止未来信息混入 |
| --- | --- | --- |
| `stock_yjbb_em` | 利润、利润/营收增速、ROE、EPS、经营现金流、行业 | 以公告日期和实际首次记录时间为边界，不以报告期末日作为可知时间。 |
| `stock_yjyg_em` | 预告类型、预测指标、变动幅度 | 只对净利润预告作风险否决；无公告时间不视为无风险。 |
| `stock_restricted_release_detail_em` | 解禁日、数量、相对流通盘比例 | 缺公告时间时用首次记录时间；丢弃接口提供的“解禁后涨跌幅”等未来结果。 |

仅有日期的公告从次日零时起可用，宁可延迟，也不假造日内公告时间。修订表不能反填旧日期：历史回放只读决策时已经存在的归档。每份输出包含 `observedAt`、`availableAt`、数据缺口及覆盖状态。接口异常、空表、字段变更和真实的零值严格区分。

接口定义以 [AKShare 官方股票文档](https://akshare.akfamily.xyz/data/stock/stock.html) 为依据。使用者需要遵守底层数据源的使用条件；开源软件许可证不等于行情数据再分发授权。安装包不含用户行情归档。

## 验证与下一阶段准入

1. 固定相同股票池、可用时间、流动性和交易费用，对比旧规则、新规则，以及逐项移除财务/事件/价格位置的版本。记录未入选样本及空仓日，避免只看赢家。
2. 稳健观察 20/60 日扣费收益下界、最大回撤与尾部损失；均衡观察 5/20 日净超额收益、RankIC 与 Precision@5；激进观察 1/3/5 日可成交命中、延续率、尾部损失和容量。触及涨停不计作能成交。
3. 时间滚动训练，训练/校准/验证分开，purge 和 embargo 不小于标签持有期。财务与事件只使用首次归档后样本；当前接口不能提供的历史可知数据不填充。
4. 使用已有事件驱动账户回测，处理 T+1、停牌、涨跌停、费用、滑点和行业集中；按交易日做成块统计，报告置信区间与各市场阶段结果。
5. 新规则先保留 `rules_unvalidated`。至少积累 60 个独立交易日的观察并按事先固定的训练/验证范围验证；若样本不足、扣费后优势不稳定、回撤恶化或覆盖不足，维持旧模型冠军，不自动发布新权重。

以上为验证门槛与工作计划，不是本版本已经获得的绩效。现有单元测试证明时间边界、风险否决和软件行为，不能证明未来投资收益。

## 私有 GitHub 与 pip

仓库保持 private；工作流只在私有 Actions 上传构建产物，不发布 PyPI，不自动改仓库可见性。未来公开前保留 GPL-3.0 与所有第三方声明，并复核发行物、依赖和数据使用条件。

需要 64 位 Python 3.11+，建议 3.12。先在仓库有读取权限的终端进行正常 GitHub 登录，切勿把令牌写入 URL 或命令历史。

研究工具：

```text
python -m pip install "stock-king[data] @ git+https://github.com/yunpengchen10/stock-king.git@main"
stock-king doctor
stock-king evidence 600519
stock-king evidence 600519 --as-of 2026-09-24T10:30:00+08:00
```

没有当时归档的历史查询会返回未知，不补抓当前数据。完整本地研究 API 将 extra 换成 `[engine]`，然后运行 `stock-king engine`。API 只监听 127.0.0.1，需要 `X-Stock-King-Token`；随机凭据保存在用户数据目录 `engine-token`，不会打印内容。模型依赖另选 `[engine,models]`，训练仍需用户选择股票池。

桌面版：从私有 Actions 下载与系统匹配的 wheel，解压 Actions 外层 ZIP 后：

```text
python -m pip install ./stock_king-2.6.0-py3-none-win_amd64.whl
stock-king
```

支持 Windows x64 和 Apple Silicon（M 系列），不提供 Intel Mac 构建。macOS 对应 `macosx_15_0_arm64` wheel（要求 macOS 15+ 和原生 ARM64 Python）。Windows 需要 WebView2 Runtime。原生 wheel 内含已有 Wails 桌面及 Python 引擎；源码安装的通用 wheel 不含编译桌面，可连接已安装应用或使用研究命令。

macOS 应用以保留符号链接和权限的内嵌归档打包，首次启动解压到用户数据目录；未做 Apple 开发者证书签名及 notarization，系统可能要求用户在隐私与安全性中允许已下载应用。Apple Silicon 发行物包含 LightGBM 和 MASTER 所需 PyTorch。

默认数据目录：Windows `%LOCALAPPDATA%/Stock King`，macOS `~/Library/Application Support/Stock King`；可通过 `STOCK_KING_HOME` 覆盖 CLI 目录。每个用户独立存储，包内不写数据库、密钥、模型或通知收件人。

CI 分别验证 Windows x64 和 Apple Silicon 的通用包安装，并构建原生 wheel；macOS 构建脚本会拒绝 Intel/Rosetta 环境。远程任务没有通过前，不能把对应平台标成已验收。
