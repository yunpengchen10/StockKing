# Stock King 账户回测与策略实验室

当前版本把 **研究标签验收** 与 **账户执行模拟** 分开展示。已有 BalancedRank 5 日、20 日时间隔离、标签结束日期检查与时间块重采样保持不变。该验收仍是重叠收盘标签的研究结果，不能直接解释为投资账户净值。账户回测也不会改变模型的 qualified 状态。

## 普通用户操作

1. 打开「策略实验室 → 账户回测」，下载 JSON 数据模板；「体验演示」只载入明确标记的合成数据，不自动运行。
2. 导入完整 JSON 数据包，或分别导入信号、行情、日历、基准 4 个 CSV。确认信号在当时已经可用，未把今天的候选名单填回过去。
3. 设置资金、目标仓位、同时持仓数、持有日、额外执行延迟、滑点及费税。仓位与费率使用小数：0.20 表示 20%，0.0003 表示万分之三。
4. 「运行账户回测」生成净值、回撤、成交记录、未成交原因与期末持仓；「同时对照：再晚 1 个交易日」以同一份输入再运行一个延迟场景。
5. 每次成功运行自动保存完整输入、参数、版本、SHA-256 与结果。在「最近保存的报告」重新打开，或导出 JSON 供复核。导出文件也可以重新导入。

模型页仅读取保存的模型与验收报告，不下载行情、不因打开页面或刷新而训练。主动训练可选择 20–200 只 A 股与 conservative / regular / aggressive 目标；优先复用面板缓存。停止在既有安全检查点进行，保留已完成缓存，可继续运行。不会自动启动 MASTER 训练。缩小股票范围没有放宽多年数据和时间隔离门槛，新模型记录有效股票与起止日期；范围外证券不会获得该小范围模型的已验证评分。

## API 与数据契约

- `GET /api/v1/quant/backtests/template` 返回 `{template, schema}`，包含可运行的合成样例与完整 Pydantic JSON Schema。
- `POST /api/v1/quant/backtests/executable` 同步执行与保存。
- `GET /api/v1/quant/backtests/reports?limit=20` 读取小型报告索引。
- `GET /api/v1/quant/backtests/reports/{report_id}` 返回保存的 `{input,result}`。编号为 64 位 SHA-256，禁止任意路径。

输入结构：

```json
{
  "dataset_name": "我的事前信号研究",
  "provenance": "user_supplied_point_in_time",
  "point_in_time_confirmed": true,
  "calendar_source": "注明实际来源与版本",
  "price_basis": "unadjusted",
  "benchmark_name": "注明所用指数",
  "calendar": ["2026-08-03", "2026-08-04", "2026-08-05"],
  "signals": [{
    "signal_id": "原始记录唯一编号",
    "symbol": "600000.SH",
    "signal_date": "2026-08-03",
    "available_at": "2026-08-03T15:30:00+08:00",
    "source": "真实信号记录的来源或模型版本",
    "side": "buy"
  }],
  "bars": [],
  "benchmark": [],
  "config": {
    "initial_cash": 100000,
    "position_weight": 0.2,
    "max_positions": 5,
    "holding_sessions": 5,
    "delay_sessions": 0,
    "commission_rate": 0.0003,
    "minimum_commission": 5,
    "stamp_tax_rate": null,
    "transfer_fee_rate": 0.00001,
    "slippage_bps": 10,
    "stop_loss_pct": null,
    "take_profit_pct": null
  }
}
```

以上是字段说明，空行情和基准会被拒绝；下载接口提供完整可运行样例。每个行情行需要 `symbol,date,open,high,low,close,volume,limit_up,limit_down`。volume 单位是股；OHLC 必须未复权、价格正数、符合高低区间。涨跌停价必须按当天证券状态导入，避免把当前 ST/板块状态倒填到过去。确实没有涨跌幅限制的日子可用 `no_price_limit:true`。停牌记录用 `suspended:true` 与当日有效估值价；不能把未知行情当停牌。`corporate_action:true` 会拒绝运行，因为当前引擎没有公司行动账务。

`benchmark` 每行需要 `date,close`，覆盖完整日历。所有涉及的证券也必须覆盖完整日历，否则不生成净值。日历必须是来源明确的实际交易日，而非简单删除周末的自然日日历。信号 `available_at` 必须包含时区，`signal_date` 必须在日历内且不晚于可用日期；`source` 和唯一 `signal_id` 必填。信号可以设置 `side:sell`、单笔 `holding_sessions`、`position_weight`。

数组也可改为 `signals_csv,bars_csv,calendar_csv,benchmark_csv` 字符串，每个 CSV 使用对应字段作为表头。日历表头为 `date`。同一项目不能同时传数组和 CSV。上限：10,000 条信号、150,000 条行情、5,000 个交易日。CSV 与 JSON 在解析后产生相同结果与指纹。

## 成交与账务规则

- 任何信号最早在**可用日期之后的下一交易日开盘**执行，再额外加 `delay_sessions`。即使可用时间为盘前，也保守推迟至下一个交易日。本版本没有分钟数据，不支持「延迟几分钟」的结论。
- 先处理已有持仓的退出，再按可用时间、信号编号顺序处理新买入。仓位预算取前一交易日账户权益，并受现金和持仓上限约束。不对已有持仓重复加仓，不把短期亏损自动转为长期持有。
- 主板/创业板买入按 100 股整数倍，科创板至少 200 股、按 1 股递增，北交所至少 100 股、按 1 股递增；无融资或负现金买入。
- 买入不能当日卖出。持有 1 日是买入次一交易日开盘退出。止损、止盈以前一收盘与入场价比较，下一开盘执行；不能把当日收盘信息用于当日开盘成交。
- 买入时开盘涨停、卖出时开盘跌停、停牌、零成交量均不成交。即使之后开板，也不凭日线假设已在原开盘成交。滑点价格超过日线可观察区间或涨跌停范围时拒绝成交。
- 买入未成交即作废，不追价；到期或触发后的退出受阻，逐交易日重试。期末持仓保留并以当日收盘估值，不伪造期末强制卖出。
- 成交金额、佣金、过户费和税按分舍入。佣金为费率与最低佣金中的较大者，印花税仅卖出收取。`stamp_tax_rate:null` 时，2023-08-28 起为 0.0005，此前为 0.001；区间仅支持 2008-09-19 以后。佣金、过户费按用户所设固定口径计算，并不自动补全所有历史费制。
- 账户每日权益 = 现金 + 持仓市值；收益、最大回撤、回撤持续交易日、相对基准差额均由权益曲线计算。胜率仅使用已平仓交易；没有平仓时为 null。基准为导入指数收盘归一化毛收益，不包含 ETF 成交费。

## 必须理解的边界

输入时间戳、来源声明和指纹有助于追溯，但不证明信号没有被事后挑选。ChatGPT 的历史复盘文字不能自动成为事前交易记录。当前候选名单不会被自动回填成历史信号；缺数据时拒绝生成绩效。

日线无法证明开盘集合竞价排队与流动性、盘口深度或真实滑点，成交仍是受约束的模拟。当前版本不处理现金分红、拆并股、权利变动、退市结算、利息、融资、软件订阅费。输入必须使用不含公司行动的区间；已调整价格不能充当真实成交价格。期末未卖出的卖出费税尚未扣除。收益与盈亏颜色按 A 股红涨绿跌。

记录保存目录：`SCREENING_DATA_DIR/quant/account-backtests/`；未配置时为 `data/screening/quant/account-backtests/`。完整报告为 `<hash>.json`，列表读取 `<hash>.summary.json`。同输入重跑产生相同指纹；实际保存时间独立记录，文件原子替换。

规则参考：[上交所交易规则（2026年修订）](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[上交所科创板投教问答](https://edu.sse.com.cn/tib/qa/)、[深交所交易规则（2026年修订）](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)。历史特殊证券、交易单位或税制如与本实现不同，应使用适合该区间的专业账务引擎。

## 验证

新增执行测试覆盖资金守恒、逐日权益、T+1、延迟跨周末、无未来成交、涨跌停、停牌/无量、未成交退出重试、期末持仓、现金/最小单位/重叠持仓约束、实际费税、缺失行情/基准拒绝、时间戳来源、CSV/JSON一致性、公司行动和无效价格拒绝、报告持久化与防路径穿越。原有 5/20 日独立验收、三档模型与任务续跑测试保持通过。没有为此运行全市场训练。
