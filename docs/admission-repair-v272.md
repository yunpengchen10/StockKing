# v2.7.2：零主推荐诊断与冷启动修复

2026-10-26。正式主推荐必须同时通过行情证据、方向、风险、已验证T+1净盈利模型和冻结买点。无合格模型仍可能是零只；不将规则分、研究观察或未经验证的预测补入正式推荐。

## 问题与修复

1. **新报价被旧目录误拦截。** 软件目录的原始选股字段可能来自上一交易日，补齐的独立 `market_quote` 已是当日新报价。旧市场情绪入口仅看目录 `stale`，导致所有候选的市场广度同时缺失。现在保留目录原标记，单独核验新报价身份、源时间、完整主板池和覆盖；缺失、过期、不完整目录仍拒绝。
2. **行业采集过度分散。** 预算内分散到很多行业却都达不到80%覆盖。现在结合轮转与历史欠缺，优先补齐行业到规定覆盖后再转下一行业；限制单行业并发，复用同一窗口已取得的有效分钟数据。完整成员分母、排除个股自身、六根完整分钟和80%要求保持不变。
3. **分钟研究对照被同股日线覆盖。** 两类记录分别保存；获正式时段、证据及血缘资格的分钟对照无需先成为正式推荐。发布记录保存实际资格和拒绝原因，T+1标签成熟且核验通过后才进入有效样本。手动扫描与历史重放不会升级训练资格。
4. **“0只通过”缺少解释。** 页面新增当前模型准备状态和独立冷启动研究区，区分模型未就绪、收益或风险拒绝、买点拒绝。样本数未知时显示未知，真实零才显示零。当前只读模型状态与历史快照分开；读取页面不训练、不重算历史推荐。
5. **Windows归档连接释放。** 市场情绪归档及只读模型状态显式关闭SQLite连接，包括异常路径，避免临时目录无法清理或轮询累积句柄。

## 验证边界

- 真实软件行情网关在2026-10-26 15:15收盘后取得主板池3,052/3,052只报价；原目录仍标为过期，新报价广度覆盖为100%，上涨占比可计算，来源为软件的新浪/腾讯行情路径。该检查使用隔离归档，保留原目录字段，不写用户学习库。
- 收盘后的采集只验证数据链路；不能代替盘中买点验证，不能证明推荐成功率改善。历史情绪样本不足仍明确显示不足。
- 回归覆盖旧目录加新报价、报价缺失/过期/身份冲突、有限采集预算、正式研究对照到T+1标签链路、手动记录不可升级、当前模型状态与历史冻结快照分离，以及组件实际渲染。
- 当前训练结构的最低日期要求由程序计算并显示；达到结构最低要求仍需通过类别、样本量、留出检验和前瞻影子验证。
- 本地安装先备份数据库与旧程序，再核对包内字节码和源码一致性。GitHub源码与本地安装更新不自动替换历史Release安装包。
