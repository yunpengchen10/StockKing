# 资金机会持续为零：采集、归档与页面诊断

2026-11-03 的一轮实际扫描研究了 306 只股票，全部被标记为个股和板块资金证据不可用。采集返回了 533 / 4792 个资金包，但归档阶段剩余预算为 0 秒，立即超时；原来的整体异常分支又清空了所有已返回资金序列。因此该轮零推荐不能解释为市场没有符合条件的股票。

另外，原采集顺序让几个分钟窗口不完整的候选行业先占用数百个请求，已有完整窗口的候选未轮到资金采集。旧 `usable` 数量只检查 3 分钟基础字段，不能说明已经取得完整 30 分钟资金或板块覆盖。

## 修复

- 在原扫描总截止时间内，资金与同行分钟使用共同截止，并提前为归档保留最多 6 秒、最终报价保留 15 秒。盘前不需要资金归档的分支不额外扣留这 6 秒。
- 逐包保存并读取归档，应用已有修订和冲突隔离。后续包失败或时间耗尽，仅使未完成核验的包不可用；此前已完成归档核验的证据保留。不存在绕过归档的资格回退。
- 资金和同行分钟共用候选优先表：新鲜、同一交易段且完整 30 分钟成交额可核验的候选先采，其余按原顺序保留。下跌与上涨候选同等处理；不看涨速、流入方向或绝对金额，完整同行集合和覆盖分母不变。
- 分别记录采集返回、旧 3 分钟字段、归档核验，以及归档后完整 30 分钟资金窗口的数量。它们均不等于最终入选数。
- 机会区区分“资金证据不可用”“仅部分可核验”“证据齐备但没有通过全部约束”与“覆盖未知”，显示窗口覆盖及归档、采集缺口。旧版历史不套用新版解释。

## 验证边界

回归覆盖采集耗尽预算后仍保留归档时间、后续归档超时不抹掉成功包、全失败不生成推荐、修订冲突继续隔离、资金和同行分钟使用同一优先表，以及真实 Vue 页面中的空结果说明。

最终相关 Python 回归 188 项通过，盘前、刷新和采集预算等相邻路径另验 52 项通过；前端全量 165 项通过并完成生产构建。打包验证逐一确认 3 个修改模块与源码一致，25,169 个其余模块和全部启动代码保持相同。

真实接口数据的隔离验证中，3 个较早闭合的 30 分钟资金窗完整，其中 2 个取得同源行情的实际同窗成交额；归档可用结果在注入后续包超时后仍被保留。已发生真实修订的末分钟仍被隔离，不因此放宽冲突规则。该验证未补齐完整板块和独立分钟身份条件，不代表这些样本已符合推荐资格。

有限公开接口探针中，东财两个发现端点由远端关闭连接；腾讯个股资金端点正常返回。探针还观察到刚完成 1–3 秒的末分钟存在迟到更新，而更早的闭合分钟在两次回复中一致。该现象不授权放宽冲突、来源或时间规则，也不说明全市场资金发现已经恢复。

修复数据管线不保证每轮有股票入选。完整板块覆盖、趋势、盘口和买入距离仍须逐项核验；不降低门槛凑数量，不回写旧扫描，不把测试结果当成未来收益验证。真实快照与接口原件仅用于本地排障，不进入仓库。
